# Capsule capture implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for inline execution, or superpowers:subagent-driven-development if the user selects that method. Steps use checkbox syntax for tracking.

**Goal:** Add a user-triggered screenshot and automatic webpage scrolling capture with preview, crop, Copy, and Save PNG.

**Architecture:** Keep pixel matching independent of Windows input and WPF. A capture session uses a small native adapter. A coordinator owns the chooser, selection overlays, progress controls, preview, shortcut, and cleanup. The existing Controller supplies entry points and temporary Capsule visibility.

**Tech Stack:** Existing C# 5, .NET Framework, WPF, System.Drawing, and Win32. No new package or browser runtime.

**Spec:** ../specs/2026-10-23-capture-design.md, approved by the user on 23 October 2026.

## Global constraints

- One capture session at a time. Website-first scrolling, initially validated with Edge and Chrome.
- One physical monitor per selection. Respect 100%, 125%, 150%, and 200% scaling.
- Scrolling is vertical at the browser's current width and zoom.
- Output limits: 32 million pixels, 32,000 rows, 120 accepted frames, 90 seconds.
- Clipboard history limits: 16 million pixels and 8 MiB PNG per image, 32 MiB PNG total, five images maximum.
- Capture does not enable clipboard history. Copy and Save require an explicit user action.
- Escape/Cancel discard. Stop keeps the verified portion and labels it partial.
- Cancel on target-window invalidation or foreground change. Pause input when the pointer leaves the capture rectangle.
- Do not log pixels, page content, addresses, or private paths.
- Use build.cmd dev and isolated test data/pipes. Never merge or replace the installed app as part of this plan.

## Review focus

1. A repeated or mostly blank page section must stop with an honest partial result instead of inventing a seam. Task 1 pins this.
2. Scrolling might be blocked or the page may still be loading. Task 2 distinguishes no movement, instability, and failure with bounded waits.
3. Negative monitor coordinates and fractional scaling must preserve the selected/cropped pixels. Tasks 2 and 3 pin the mapping.
4. Mouse movement toward Stop must not discard the result or steal browser focus. Tasks 2 and 3 pin pause/stop behavior.
5. Copying a large capture must not bypass the history budget or leave a full-size source behind a thumbnail. Task 4 pins ownership and limits.

## File map and common interfaces

New src/Capture.cs owns the pure pixel types, limits, and stitcher.
New src/CaptureSession.cs owns orchestration and the desktop interface.
New src/CaptureDesktop.cs owns native screen reads, browser eligibility, window checks, scrolling, and timing.
New src/CaptureSelection.cs owns the mode chooser, per-monitor selection overlays, and non-activating progress controls.
New src/CapturePreview.cs owns preview, pan/zoom, crop, Copy, and Save.
New src/CaptureCoordinator.cs owns the UI/session lifecycle and additional shortcut.

Common types:
- CaptureMode: Screenshot or Scrolling.
- CaptureFrame(int width, int height, byte[] pixels): owned BGRA32 pixel buffer, tightly packed rows. Exposes Width, Height, Pixels.
- CaptureRequest: Mode, Area as RECT, Target as IntPtr, and TargetBounds as RECT.
- CaptureResult: Image as CaptureFrame, Partial as bool, Notice as string.
- CaptureProgress: frame count, accumulated rows, paused flag, short status text.
- CaptureLimits: constants with the exact global values above.
- StitchResult: AddedRows as int, Matched as bool, Unchanged as bool, Notice as string.

## Task 2: Cancellable capture session and native adapter

**Files:** Create src/CaptureSession.cs, src/CaptureDesktop.cs, and tests/CaptureSessionTests.cs. Modify tests/Tests.cs.

**Interfaces:**
- Consumes CaptureFrame, CaptureStitcher, CaptureLimits, and StitchResult from Task 1.
- Produces CaptureMode, CaptureRequest, CaptureResult, and CaptureProgress as defined in the common interfaces.
- ICaptureDesktop exposes NowMs, TargetValid(CaptureRequest), EscapePressed, PointerInside(RECT), ReadFrame(RECT), Scroll(CaptureRequest, int direction), and WaitAsync(int milliseconds, CancellationToken).
- CaptureSession(ICaptureDesktop desktop) exposes RunAsync(CaptureRequest request, CancellationToken cancel), Stop(), and a Progress event carrying CaptureProgress.
- RunAsync returns CaptureResult for a finished/stopped/limited capture. Cancellation discards frames and throws OperationCanceledException.
- CaptureDesktop implements ICaptureDesktop and supplies selection/window eligibility helpers and physical pixel conversion helpers used by Task 3.

- [ ] Test pointer outside area pauses scrolling. Stop while paused must return the verified partial result. Cancel while paused must discard it.
- [ ] Test initial modifier release with a five-second bound. Never scroll while Ctrl/Alt/Shift/Win remain pressed.
- [ ] Test coordinate conversions on negative-origin monitors at scales 1.0, 1.25, 1.5, and 2.0.

## Task 3: Selection, progress, and preview UI

**Files:** Create src/CaptureSelection.cs, src/CapturePreview.cs, and tests/CaptureViewTests.cs. Modify tests/Tests.cs and src/Preview.cs.

**Interfaces:**
- Consumes Task 1 pixel types and Task 2 request/progress types and physical conversion helpers.
- CaptureChooser raises a chosen CaptureMode or cancellation.
- CaptureSelection.Open(CaptureMode) returns a Task<CaptureRequest>; it closes all overlays before returning and cancels on Escape.
- CaptureProgressWindow exposes StopRequested and CancelRequested and accepts CaptureProgress updates. It does not activate when clicked.
- CapturePreviewWindow(CaptureResult result, Func<CaptureFrame, bool> copy = null, Func<CaptureFrame, bool> save = null) displays the image and notice. It raises RetakeRequested and Closed. Defaults handle Copy and Save on the STA UI thread; tests supply delegates.
- CapturePreviewWindow.CropPixels(CaptureFrame source, RECT pixels) returns the exact bounded crop for tests.

**Interfaces:**
- Consumes Tasks 1 through 3.
- CaptureCoordinator(Action<bool> captureVisibilityChanged) exposes Open(), RegisterShortcut(string text) returning bool, Busy, and Dispose().

- Controller owns one coordinator. It temporarily suppresses Capsule visibility while selection/capture runs, releases held prompts to their hosts, and restores visibility using current config/fullscreen state.
